# 抖音评论获客工作流 v0.2.0

2026-10-03。用户确认：画像由使用者配置，默认越南签证办理需求；模型由使用者从 FutureStaff 平台当前主体的授权模型中选择。监控/筛选与定时私信是独立功能。

## 模型边界

复用 `fs-platform-access` 的 Host-only `platformInference` 服务。模型目录来自平台授权响应，`authorizeChat(selectedModelId)` 每次验证当前会话及所选模型，保留默认聊天兼容性。所选 modelId 不构成主体授权；tenant/user/access token 由 Host 恢复。供应商密钥不进入本机或 renderer；本次不配置凭据、不做真实推理。

现有传输固定 DEV `/desktop/v1/chat` 和版本 0.1.0，不新增平台 API、Schema 或权限。切换主体/注销会中断模型请求。独立分析调用不保留聊天历史，临时归属绑定在调用结束后清除。

## 画像、检索及判断

`TargetProfile` 包含名字、版本、业务目标、包含/排除条件、种子词、正反例和审核方式。默认要求明确签证办理/咨询/协助意图；排除旅游兴趣、已办完且无新需求、同行广告及转述。不猜测国籍、身份或办理资格，不提供签证政策判断。

AI 按直接办理、费用流程、办理障碍、出行场景生成最多30个检索词；URL、任意代码、超限和重复分组被拒绝。关键词只是查找内容的条件，不是用户命中凭据。

模型判定输入只含标题、描述、当前评论、父评论及时间，不发送 secUid、昵称、评论/作品ID。输出严格 JSON：target/uncertain/excluded、需求、原因、明确紧急性及逐字证据。引用不存在的原文则拒绝；target 只有标题证据时降为 uncertain；模型不得生成收件人或发送操作。

## 本地工作区核心

`LeadWorkspace` 接收可信 Host principal，拒绝跨主体状态文件/分析结果。账号列表与作品列表分别保存 ID、固定来源 URL、扫描间隔、启停和下次扫描时间。只接受显式抖音主页/视频/图文链接，不展开未知短链。

可信采集器调用 `recordScan` 提交已关注作品的新评论，按作品+评论ID去重，不暴露模型可伪造内容的任意入库工具。保留评论、判定、规则/模型版本和候选用户证据；同用户多处评论合并。关注账号的新作品发现、关键词检索和页面翻页需要后续采集器接入，本地列表本身不是正在运行的监控服务。

规则变化递增版本并撤销旧审核，模型/规则切换后的在途结果拒绝落库。拒绝联系及已联系状态不会被新评论覆盖。人工审核为默认；使用者可显式选择高意向自动入选（eligible），这不等于外部发送授权。

审核后 `messagePlan` 生成名单发送草稿，仍需原有 DSH 预览和启动审批。可选 scheduledAt 指定绝对时间；最长预约7天、执行窗口最长1小时，不能使用已过期时间。进程重启不恢复启动授权。一次性预约不是每天/循环发送：周期规则、每天额度和运行恢复需后续调度接入。

未来 Host 集成必须将工作区规则变更、拒绝联系、注销和主体切换同步到待发送任务，暂停/撤销失效的冻结计划；在每条发送前重查候选资格。当前独立 DM MCP 还没有接入工作区账本，不能宣称该撤销链已实现。

状态文件只放受保护、忽略的 `work/`，由独占 `FileStore` 存储。不新增数据库，不将评论和用户数据写入仓库或日志。不注册共享桌面模块，也不修改原 Local Runner 的只读能力。

## 交付状态与下一原子任务

本轮完成可测试的默认画像、关键词/评论分析、用户所选平台模型 Host 服务、本地关注/候选库核心、一次性定时发送核心。核心类通过注入 Host inference port 使用；未连接独立 stdio MCP、正式桌面页面或实时采集循环。

后续需完成：关注账号/作品及候选列表 UI、模型选择控件、受控关键词检索/账号新作品发现/增量评论采集、主体隔离的 Host 装配、周期调度及拒绝联系撤销链、真实 DOM 校准。它们不是本轮测试通过的能力。按照仓库 Atomic Task 边界拆分交付，不把业务类存在视为软件功能已经可用。

验收包括：所选模型授权/拒绝/注销取消、严格证据校验、用户可定义画像、去重与扫描进度、跨主体拒绝、在途旧结果丢弃、拒绝联系、审核与发送授权分离、预约时间和原发送回归。
