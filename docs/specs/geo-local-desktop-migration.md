# GEO 桌面本地迁移规格

日期：2026-10-10。状态：用户已确认复用 DSH 身份/模型并要求与抖音同级；本地迁入和隔离验证已完成，未更新运行中的软件或生成新安装包。

## 目标与假设

将 GEO 已实现的业务能力迁入 FutureStaff Agent 的默认桌面底座，以系统标签页打开，在本机保存业务数据。用户仅安装桌面安装包，无需另装 Docker、PostgreSQL、Redis 或独立 Web 服务。

当前假设：本地化指界面、业务存储和任务状态本地化；身份、应用权限和模型能力继续由 Platform/DSH 提供。它不是完全离线产品。真实收费验证、浏览器采集、文章发布、导入线上数据、发布安装包和修改运行中的软件不在本次自动执行范围。

## 技术方案与代码归属

在客户端新增 `plugins/fs-geo`（Host、本地业务服务与构建后的 GEO 界面），复用 `platformSystemPages` 系统标签页。保留 GEO 的业务页面与领域模型，去掉独立 GEO 登录页，身份由 DSH Host 恢复。React 19 页面使用隔离的本地静态资源及明确受控桥接，避免与 DSH React 18 混用同一渲染器；不将远程 GEO 网站嵌入后称为本地化。

优先使用 GEO 测试已验证的 PGlite 内嵌数据库，并将 WASM/运行资源纳入安装包。保留现有 SQL、复合外键、FORCE RLS、事务、版本与幂等账本，不用 SQLite 字符串替换模拟 PostgreSQL。PGlite 必须验证在安装包 Electron Node 模式中的文件持久化、重开及事务/RLS 行为；若不兼容，先报告证据再调整存储方案。

GEO SaaS 仓保持独立。本次迁入采用固定来源版本的业务代码及资源清单，记录迁入路径、原 SHA、后续差异和同步方式，不复制 .git、依赖、dist、部署配置、服务器密钥或真实数据。不修改生产 GEO 运行方式，不连接生产数据库。

预计涉及：新插件；源代码来源清单；`profile/futurestaff-alpha`；`fs-platform-access` 的工作区代码安装与生命周期；Profile 发布暂存脚本；桌面安装包资源/闭包测试。不得将迁入逻辑写入任一上游子模块。

## 身份、权限与本地数据

- 本地目录按可信 environment / tenant / user 工作区隔离。一个主体一份品牌在当前成员的本地库内成立；不同设备和成员的本地副本不会自动共享。共享协作和云同步不在本轮范围，界面必须说明此差异。
- 本地请求接受固定路径、回环来源、同源上下文和有限大小；每个业务请求从 Host 验证身份。客户端 tenantId、文件路径、模型输出和页面状态均不能授权。
- `authorizeLocal()` 当前只给出 tenant/user，不能被视作 GEO 管理员权限。权限适配必须取得 Host 验证过的 GEO 应用授权和 `geo.read / geo.operator / geo.admin`，逐请求检查；未获得这些信息时失败关闭，不能把所有桌面用户硬编码成管理员。
- 先核验已有 `issueApplicationToken('geo')` 的授权响应和 audience 是否可消费；不修改 Platform 权限或自动开通主体。平台缺少相应契约时，真实操作保持不可用，隔离测试用明确 fixture 验证各角色。
- 注销、身份撤销和工作区变化须取消请求，释放数据库/任务资源并移除页面；旧数据原地保留，不自动复制到另一个主体。

## 模型、证据和外部动作

不复制 `GEO_AI_SERVICE_TOKEN`、供应商 Key、GEO Cookie 或 Platform 签名密钥。DSH 当前 `platformInference` 提供授权模型与纯文本结果；它不提供 GEO SaaS 模型系统归集、引用元数据或费用明细的等价保证。

先定义 Host 模型适配端口，验证 GEO 应用权限与授权模型范围。只有平台契约明确允许时才接通真实测量/起草；不默认将 desktop 聊天权限升级为 GEO 系统权限。每次调用是显式用户动作；异常结果持久化为 UNKNOWN，不自动再收费重试。不调用模型即可做本地录入、文章编辑、审核、排期与分析；逐请求 GEO 权限核验仍需要平台可用，不承诺完全离线授权。

纯文本推理不能宣称已联网或获得来源引用：搜索状态和引用能力按实际响应标记 UNKNOWN/UNSUPPORTED；正文链接和 provider 引用分开；失败不按零统计；导入证据保留 MANUAL_IMPORT。草稿不是测量证据，发布链接不是 AI 引用证据。

账号登录、定时任务和真实发布适配器不直接从原系统带入自动启用。第一轮保留手动发布待办、冻结文章版本及人工回填；自动执行接口继续失败关闭，不降级立即发布，不读取现有 Cookie 或浏览器 Profile。

## 分阶段交付

1. 本地基础：固定 GEO 源码清单、插件骨架、嵌入数据库、可信身份/权限端口和系统标签页；用全新临时库验证隔离和重开。
2. 完整离线业务：品牌、推广计划、问题、证据、统计/导出、选题、文章版本、审核、手动排期与回填；覆盖原功能，而非只有一个入口或只读演示。
3. 模型适配与桌面打包验证：模型目录/起草/测量使用替身先验收；验证任务未知状态、防重复、资源路径及安装包内运行。真实收费或外部动作另行授权。

已有登录提示优化独立保留；不覆盖 `tasks/system-browser-tabs.md` 的未完成需求。规格批准后记录本迁移的独立任务和验证证据，再逐项实施。

## 命令与测试

现有 GEO 基线：`npm run typecheck`；`node --import tsx --test --test-concurrency=1 tests/*.test.ts`（在 GEO 仓运行）。仅使用隔离测试数据库，不加载真实服务配置。

新插件拟定：在客户端根运行 `npm run build -w @futurestaff/fs-geo`、`npm run typecheck -w @futurestaff/fs-geo`、`npm test -w @futurestaff/fs-geo`。测试结构和命令将随具体 manifest 一起固定，不能报告未创建的命令已通过。

客户端相关回归：登录插件 Node 测试、系统标签页测试、工作区资源升级测试、Profile 暂存/安装包资源测试。稳定版/Beta 桌面测试应顺序运行，避免其共用临时状态文件干扰。

验收包括：错误身份/未开通/只读拒写/跨主体资源拒绝；离线全业务闭环；重开不丢失；两个主体及两个成员目录不互见；未知 AI 结果不重试；CSV 防公式注入；草稿不覆盖未保存正文；冻结版本不受新编辑影响；注销后拒绝读写；WASM/SQL/界面资源可从安装包加载。前端样式只作用于 GEO 范围，保留既有界面结构和键盘操作。
